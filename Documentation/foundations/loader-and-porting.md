# Loader, compatibility and porting

Use the [117 changes](https://jakobharder.github.io/anno-mod-loader/changes-117/) and the game labels in the [Modloader Reference](https://jakobharder.github.io/anno-mod-loader/). The Anno 1800 stable branch is a historical comparison. See the local cross-game audits for concrete examples of shared structures, changed contracts and old names. [1800 comparison](../reference/anno-1800-comparison.md) For offline reproduction, record the xmltest build and verify the actual output.

| Subject | Transferable pattern | 117-specific requirement |
| --- | --- | --- |
| File layout | Mirror the exact virtual path and use small, focused patches. | Asset patches normally go in `data/base/config/export/assets.xml`; translations in `data/base/config/gui/texts_<language>.xml`. Verify exceptions from the archive. |
| Metadata | Stable author-specific ModID, semantic version, explicit compatibility intent. | Use top-level `modinfo.json`, integer `"Anno": 8`, `Difficulty`, and documented `GameSetup` fields. Existing short versions, `Difficulty: "cheat"` and `.jsonc` metadata need version-specific verification before reuse. |
| Dependencies | Distinguish required mods, optional integrations and load order. Avoid circular relationships and broad late loading without a reason. | For new work use `Dependencies.Require`, `Optional`, `LoadAfter`, `Deprecate`, `Incompatible`. A missing `Require` is documented as a warning; check actual activation. Legacy flat fields in this repo do not prove how 3.0 handles them. |
| Asset model | Inspect templates, BaseAssetGUID, property defaults and list keys; use GUIDs and narrow anchors. | Re-audit each target and follow the [117 GUID registry](https://github.com/anno-mods/GuidRanges/blob/main/117/guids.md). The numeric mod ranges carry over; individual reservations and native GUIDs are game-specific. |
| XML operations | Legacy `Type` plus `Path`, GUID targets, groups/includes and dynamic content are available; XPath anchors matter. | 117 also documents short attributes, direct `Asset` insertion, `Property` lookup, `MaxRepeat`, XPath functions, ModID/options variables, `ModItem` and `ModValue`. Check each feature and supported build. The reference documents an early direct-Asset workaround; test before assuming it remains necessary. |
| Localization | Patch text exports, use consistent IDs across languages, retain placeholders. | Use `Text/OasisId` in assets and `LineId` in text exports. Never port 1800's text GUID lookup or lose precision of large negative native IDs. |
| InfoTips | Match the target and use loader-aware validation. | Patch `data/infotips/export.bin` via `export.bin.xml`. 117's attributes for InfoElements/VisibilityElements and hidden counts differ from the 1800 XML view. Verify the actual exported format and lookup. |
| Resources | Keep custom files under unique paths; exact replacement paths are conflict points. | Use 117-aware tools; CFG/FC, model, island, audio and save containers require a separate audit. Similar extensions do not prove compatible contents. |
| Options/profiles | Isolate configurations for testing. | `active-profile.txt` is documented under the user mods directory; the overview gives a shorter conflicting path. Native mod options use `active-options.jsonc` and metadata defaults. Do not copy 1800 `activation.json`. |
| Scripts/save/MP | Audit effects, ownership, persistence and timing; test peers separately. | Use the [Luau and runtime chapter](luau-and-runtime.md). Neither 1800's shared Lua libraries nor its network/timing recipes are drop-in contracts. |

For new GUIDs and positive mod LineIDs, inspect the 117 registry, current Vanilla and relevant dependencies/other local packages. The documented mod range is 1,337,471,142–2,147,483,647; the reference reserves 2,001,000,000–2,001,009,999 for personal use. Preserve a mod's already published IDs. The 117 registry assigns Serp's Mods the range 1,500,000,000–1,500,010,000. The parent-directory note's old “free from” value records a point in time. Check actual allocations and packages before selecting an ID within the authorized range. [117 GUID registry](https://github.com/anno-mods/GuidRanges/blob/main/117/guids.md)

When patching XML, read [basic operations](https://jakobharder.github.io/anno-mod-loader/modops/basics/), [conditions](https://jakobharder.github.io/anno-mod-loader/modops/control/), [content](https://jakobharder.github.io/anno-mod-loader/modops/content/) and [lists](https://jakobharder.github.io/anno-mod-loader/modops/lists/). Check the context: in assets, the `GUID` attribute selects an Asset; `@GUID` lookup starts under its Values. Distinguish selector success from recursive-merge behavior, especially for `Item` siblings and absent parents. Select existing entries by stable identity, assert which items survive, and limit broad selectors to a documented intent. Treat the [generic XPath cheat sheet](https://devhints.io/xpath) as syntax help, not a list of functions supported by the game. See [loading order](https://jakobharder.github.io/anno-mod-loader/loading-order/) for the normal and late phases and [options](https://jakobharder.github.io/anno-mod-loader/options/) for defaults and overrides.

Keep nested packages visible in a compatibility review. According to the [patch review](../reference/changelogs.md), 2.0 blocks multiplayer start on mismatched mod versions/setups, and 3.0 adds comparison of sub-mods. Compare IDs, versions and actual contents on every client. A path match or matching parent ModID alone is insufficient. See the [workspace duplicates](../reference/workspace.md).
