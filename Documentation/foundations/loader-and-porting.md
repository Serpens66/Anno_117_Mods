# Loader, compatibility and porting

Use the [117 changes](https://jakobharder.github.io/anno-mod-loader/changes-117/) and the game labels in the [Modloader Reference](https://jakobharder.github.io/anno-mod-loader/). The Anno 1800 stable branch is a historical comparison. See the local cross-game audits for concrete examples of shared structures, changed contracts and old names. [1800 comparison](../vanilla/anno-1800-comparison.md) For offline reproduction, record the xmltest build and verify the actual output.

| Subject | Transferable pattern | 117-specific requirement |
| --- | --- | --- |
| File layout | Mirror the exact virtual path and use small, focused patches. | Asset patches normally go in `data/base/config/export/assets.xml`; translations in `data/base/config/gui/texts_<language>.xml`. Verify exceptions from the archive. |
| Metadata | Stable author-specific ModID, semantic version, explicit compatibility intent. | Use top-level `modinfo.json`, integer `"Anno": 8`, `Difficulty`, and documented `GameSetup` fields. Existing short versions, `Difficulty: "cheat"` and `.jsonc` metadata need version-specific verification before reuse. |
| Dependencies | Distinguish required mods, optional integrations and load order. Avoid circular relationships and broad late loading without a reason. | For new work use `Dependencies.Require`, `Optional`, `LoadAfter`, `Deprecate`, `Incompatible`. A missing `Require` is documented as a warning; check actual activation. Legacy flat fields in this repo do not prove how 3.0 handles them. |
| Asset model | Inspect templates, BaseAssetGUID, property defaults and list keys; use GUIDs and narrow anchors. | Re-audit each target and follow the [117 GUID registry](https://github.com/anno-mods/GuidRanges/blob/main/117/guids.md). The numeric mod ranges carry over; individual reservations and native GUIDs are game-specific. |
| XML operations | Legacy `Type` plus `Path`, GUID targets, groups/includes and dynamic content are available; XPath anchors matter. | 117 also documents short attributes, direct `Asset` insertion, `Property` lookup, `MaxRepeat`, XPath functions, ModID/options variables, `ModItem` and `ModValue`. Check each feature and supported build. The reference documents an early direct-Asset workaround; test before assuming it remains necessary. |
| Localization | Patch text exports, use consistent IDs across languages, retain placeholders. | Use `Text/OasisId` in assets and `LineId` in text exports. Never port 1800's text GUID lookup or lose precision of large negative native IDs. |
| InfoTips | Match the target and use loader-aware validation. | Patch `data/infotips/export.bin` via `export.bin.xml`. 117's attributes for InfoElements/VisibilityElements and hidden counts differ from the 1800 XML view. Verify the actual exported format and lookup. |
| Resources | Keep custom files under unique paths; exact replacement paths are conflict points. | Use 117-aware tools; CFG/FC, model, island, audio and save containers require a separate audit. Similar extensions do not prove compatible contents. |
| Options/profiles | Isolate configurations for testing. | Earlier instructions name `active-profile.txt`; inspection of Serp's installation on 2026-11-12 found `mods/profile.txt` selecting `mods/profiles/default.txt`. Follow the actual generated configuration. [Installation checks](../setup.md#verify-installation-and-startup-activation), [D117-11](../mods/discrepancies.md). Native mod options use `active-options.jsonc` and metadata defaults. Do not copy 1800 `activation.json`. |
| Scripts/save/MP | Audit effects, ownership, persistence and timing; test peers separately. | Use the [Luau and runtime chapter](luau-and-runtime.md). Neither 1800's shared Lua libraries nor its network/timing recipes are drop-in contracts. |

For new GUIDs and positive mod LineIDs, inspect the 117 registry, current Vanilla and relevant dependencies/other local packages. The documented mod range is 1,337,471,142–2,147,483,647; the reference reserves 2,001,000,000–2,001,009,999 for personal use. Preserve a mod's already published IDs. Use the range authorized for the package author and check its actual allocations. Serp package ownership is recorded with the repository's mod documentation. [Serp allocations](../mods/guid-allocations.md) [117 GUID registry](https://github.com/anno-mods/GuidRanges/blob/main/117/guids.md)

When patching XML, read [basic operations](https://jakobharder.github.io/anno-mod-loader/modops/basics/), [conditions](https://jakobharder.github.io/anno-mod-loader/modops/control/), [content](https://jakobharder.github.io/anno-mod-loader/modops/content/) and [lists](https://jakobharder.github.io/anno-mod-loader/modops/lists/). Check the context: in assets, the `GUID` attribute selects an Asset; `@GUID` lookup starts under its Values. Distinguish selector success from recursive-merge behavior, especially for `Item` siblings and absent parents. Select existing entries by stable identity, assert which items survive, and limit broad selectors to a documented intent. Treat the [generic XPath cheat sheet](https://devhints.io/xpath) as syntax help, not a list of functions supported by the game. See [loading order](https://jakobharder.github.io/anno-mod-loader/loading-order/) for the normal and late phases and [options](https://jakobharder.github.io/anno-mod-loader/options/) for defaults and overrides.

Keep nested packages visible in a compatibility review. According to the [patch review](../vanilla/changelogs.md), 2.0 blocks multiplayer start on mismatched mod versions/setups, and 3.0 adds comparison of sub-mods. Compare IDs, versions and actual contents on every client. A path match or matching parent ModID alone is insufficient. See the [workspace duplicates](../mods/workspace.md).

## Phoenix HUD compatibility

Anno 117 HUD scenes and widgets under `data/ui/studio/generated/` are binary Phoenix resources. The published loader reference documents no additive patch type or XML sidecar for `PHXSC` or `PHXWI`. The InfoTip `export.bin.xml` mechanism handles a specific separate resource. The local Anno Toolbox 0.2.0 guide (`docs/mod-diff.md`) treats ordinary same-path files as a whole-file collision and describes the later file as taking precedence. `Dependencies.LoadAfter` can order a compatibility package's resolved replacement. A two-mod same-path precedence test in the installed game remains open. [Loader reference](https://jakobharder.github.io/anno-mod-loader/changes-117/) · [InfoTip patch contract](https://jakobharder.github.io/anno-mod-loader/infotips/) · [Load order](https://jakobharder.github.io/anno-mod-loader/loading-order/) · [Anno Toolbox](https://github.com/SunnyM00n/anno-toolbox)

### Combine existing HUD replacements

1. Compare each package's scene with the effective native scene for its supported build. Identify additions, removals and changes by instance identity and binding endpoint. Audit shared assets as well as scene files. Inselbar 0.4.25 also replaces the native `Good_Atom` widget. [Native and package evidence](../vanilla/research.md#hud-scene-resources-and-writable-bindings-2026-11-24)
2. Apply the intended changes to one decoded base. Preserve ordering, grouping, unique instance identities, widget references, layout, input/visibility rules and animations. Rebuild binding paths, event/assignment destinations, constants and converter parameters. Phoenix stores graph endpoints as indices into file-local tables, so a copied node or index may resolve to a different object in the combined scene. Keep each external resource at its intended path and resolve edits to the same resource explicitly. [Phoenix inspection](../tools/README.md#inspect-phoenix-ui-resources)
3. Inspect Lua writers and readers as part of the merge. If both packages write the same native property, give them distinct bindings or coordinate the writers through one owner. For Inselbar, evaluate both `CurrentTabName` and `Second_Third_PartyName`, including their native consumers. Check UI position and overlapping drop targets separately from the resource and binding checks.
4. Encode and validate one complete resource per affected path. A compatibility package can require both supported mods and specify both in `LoadAfter`. Scope it to the reviewed game and mod versions, check originals independently and test the combination in a separate profile when authorized. Check the relevant HUD panels, drag/drop, visibility and input, plus save and multiplayer behavior where applicable.

**Offline proof, 2026-11-24.** Local Anno Toolbox 0.2.0 re-encoded both native scenes and both Inselbar scene replacements byte for byte. A separate in-memory test inserted two synthetic instances derived from the sample widget instance into the effective native `hudarchivesscene`, using `phoenixedit.clone_object`, `adopt` and `insert_object`. The test authored a separate assignment per instance with `uiedit.bindings.Editor.add` and saved with `phoenixwrite.save`. Decoding the result gave three top-level instances and seven bindings. All five original bindings kept their endpoints and settings, and the two new bindings resolved to distinct instance GUIDs. A second test added one independently bound instance to the actual Inselbar archive scene and decoded three instances and ten bindings. All nine existing binding paths and converter bytes were preserved. Re-encoding both combined scenes reproduced their bytes. This verifies structural composition and the codec on the tested scenes. Game rendering, loader precedence and a merge of two released HUD mods remain untested.

### Design independently installable extensions

Cooperating authors can design a shared HUD base that owns the native scene replacement and declares extension points up front. Give each contribution a distinct resource path and a prewired slot with a fallback, or build the selected contributions into a single scene before installation. Keep separate layout areas and an explicit interface for UI data and input ownership. Phoenix container instances can reference separate widget files. A shared slot design and its fallback behavior still need an isolated runtime test. The native API audit found no Lua registration entry point for new scene instances.
